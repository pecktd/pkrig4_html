Development

How to run the tests, set up VS Code, regenerate the editor stubs, and release a new version.

Tests

The suite runs headless in mayapy and takes about a second:

"C:/Program Files/Autodesk/Maya2024/bin/mayapy.exe" tests/run.py [-v] [pattern]

tests/run.py starts Maya, makes sure it imports this checkout of pkrig4 (a userSetup.py may already have imported another one), runs every tests/test_*.py with unittest, and exits non-zero on failure. Each test starts from an empty scene.

If PYTHONPATH contains a folder of Maya completion stubs, mayapy imports those instead of the real maya.cmds, and every call returns None. tests/run.py detects this and stops with the path to remove.

Editor setup

Two sets of generated stubs give VS Code (Pylance) completion and accurate types. Both are produced from the running Maya and committed, so the editor works without Maya.

FileGeneratorProvides
node.pyiscripts/generate_stubs.pyEvery node type as a class with its attributes
typings/maya/scripts/generate_maya_typings.pymaya.cmds, maya.mel, maya.standalone and the OpenMaya 2.0 modules

Regenerate both after a Maya upgrade, or to include more plugin node types:

"C:/Program Files/Autodesk/Maya2024/bin/mayapy.exe" scripts/generate_stubs.py
"C:/Program Files/Autodesk/Maya2024/bin/mayapy.exe" scripts/generate_maya_typings.py

Point the editor at pkrig4's parent folder and Maya's own packages with a machine-local .env (not committed):

PYTHONPATH="C:/dev;C:/Program Files/Autodesk/Maya2024/Python/Lib/site-packages"

pyproject.toml tells pyright/Pylance to read typings/, and turns off the "unused expression" check that would otherwise flag every src >> dst line.

Code style

  • Format with black (line length 100); lint with ruff (configured in pyproject.toml, imports grouped as standard library, Maya, then pkrig4).
  • Google-style docstrings. Mark example code with Example:: and indent it; this manual renders it as a code block.
  • List public names in each module's __all__; this manual documents exactly those.
  • Read the scene with OpenMaya 2.0, change it with maya.cmds, and never rely on the selection.
  • Return a named tuple when a function makes several nodes, and only add fields at the end.

Versioning

pkrig4 follows semantic versioning: MAJOR.MINOR.PATCH. Below 1.0, the API may still change between minor versions. The current version is 0.0.2.

  1. Bump __version__ in __init__.py and the "Current version" line in the README in the same change; tests/test_version.py fails if they disagree.
  2. Tag the commit vX.Y.Z so every release can be checked out.
  3. Rebuild this manual from the new version.

Build scripts can stamp pk.__version__ onto the rig, so a published rig records which pkrig4 built it.

Rebuilding this manual

The manual lives in the pkrig4_html repository. Its reference pages are generated from pkrig4's docstrings, so documentation changes belong in the code:

"C:/Program Files/Autodesk/Maya2024/bin/mayapy.exe" build.py --pkrig4-parent C:/dev

The output goes to docs/, which GitHub Pages serves.
