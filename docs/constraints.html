pkrig4.constraints

constraints

Constraints that return typed nodes and take per-target weights.

from pkrig4 import constraints

constraints.parent_constraint(arm.upper_arm_jnt, sleeve_zr, maintain_offset=True)
constraints.point_constraint([a, b], loc, weights=[0.25, 0.75])
constraints.constrain_to_skin_weights("body_GEO.vtx[812]", button_zr)

drivers may be one node or a list. Parent and orient constraints use shortest-path rotation interpolation, so blended rotations don't flip.

def aim_constraint(
    drivers: Drivers,
    driven: Node | str,
    *,
    aim_axis: Sequence[float] = (0, 1, 0),
    up_axis: Sequence[float] = (1, 0, 0),
    up_vector: Sequence[float] = (0, 1, 0),
    up_object: Node | str | None = None,
    up_rotation: bool = False,
    maintain_offset: bool = False,
    weights: Sequence[float] | None = None,
    **flags: Any,
) -> node.aimConstraint

Aim aim_axis at the drivers; up_axis follows up_vector or up_object.

With up_object, up_axis points at the object; with up_rotation as well, it follows up_vector in the object's space instead, so it turns with the object without depending on where the object is.

def constrain_to_skin_weights(
    vertex: str,
    driven: Node | str,
    *,
    ignore_below: float = 0.001,
) -> node.parentConstraint

Parent-constrain driven to the joints that skin vertex, with the same weights.

Influences below ignore_below are dropped and the rest renormalised to sum to 1, so the constraint follows the vertex the way the skin does.

Raises
ValueError
The mesh has no skinCluster, or the vertex has no weights above ignore_below.
