pkrig4.node

node

Maya node types as classes.

from pkrig4 import node

md = node.multiplyDivide()                 # create a new node
md.i1x.value = 2                           # attributes by short or long name
jnt = node.joint.wrap("L_arm_jnt")       # wrap an existing node, type-checked

Each class is built from the Maya node type of the same name the first time it is used, as a subclass of the matching pkrig4.core wrapper (joint → Joint, locator → DagNode, ...). Any type Maya knows works, including plugin types once the plugin is loaded.

node.pyi (generated by scripts/generate_stubs.py) declares every class with its attributes, so the editor autocompletes both node.multiplyD… and md.i1….

Creating and wrapping

CallDoes
node.<type>(name=None, *, parent=None)Creates a node of that type without changing the selection. Shape types created without a parent get a new transform; the shape is returned.
node.<type>.wrap(node)Wraps an existing node, given a name, a wrapper or an MObject. Raises TypeError if it isn't that type or a subtype (node.transform.wrap(a_joint) is fine), and ValueError if no node, or more than one, matches the name.
dir(node)Lists every node type Maya knows, including types from loaded plugins.

Each class is a subclass of the matching core wrapper, so it has all of that wrapper's methods, and isinstance(md, node.multiplyDivide) works:

ClassInherits from
node.jointJoint → Transform → DagNode → Node
node.transformTransform → DagNode → Node
node.locator, node.mesh, other shapesDagNode → Node
Everything else (node.multiplyDivide, …)Node

How it works

No class is written out per node type. The first time you use node.multiplyDivide, the module checks that Maya knows the type, builds the class, and caches it. Attribute access like md.i1x goes through Node's generic attribute lookup, so no per-attribute code exists at runtime either.

The editor can't see classes that are built while Maya runs, so a generated stub file, node.pyi, describes all of them: one class per node type, following Maya's own type hierarchy, with each type's attributes under their long and short names. VS Code reads it for completion and never runs it. See Development for regenerating it.

Plugin types work at runtime once their plugin is loaded. Before that, node.eulerToQuat raises AttributeError: Maya has no node type 'eulerToQuat'; is its plugin loaded?. Abstract types such as dagNode can be used with wrap() but not created.
