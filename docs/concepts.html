Concepts

Everything in pkrig4 builds on a few ideas: typed nodes, attributes as objects, one naming convention, and edits that can always be undone.

Nodes

Use node.<type> whenever you know the node type while writing code. It creates a new node, or wraps one that already exists in the scene and checks its type:

from pkrig4 import node

md = node.multiplyDivide("L_arm_stretch_mdv")      # create
grp = node.transform("L_arm_grp", parent="rig_grp")
jnt = node.joint.wrap("L_arm_jnt")                 # wrap an existing joint
node.joint.wrap("persp")                           # TypeError: persp is a transform, not a joint.

Every node is one of four wrapper classes from core, picked automatically:

ClassForAdds
NodeAny nodename, type, attribute access, add_attr, lock_and_hide, delete
DagNodeAnything in the DAG, shapes includedparent, children(), shapes(), full_path, world_matrix
TransformTransformsworld_position, match(), freeze(), reset(), axis()
JointJointsEverything a transform has

So node.joint() is a Joint and node.locator() (which returns the shape) is a DagNode. When the type is only known at runtime, use the untyped forms pk.create(type_name) and pk.wrap(name).

A wrapper holds Maya's handle to the node, not its name. It keeps working after the node is renamed or reparented, and two wrappers of the same node compare equal.

Attributes

Any attribute is reachable as a Python attribute, by long or short name, including dynamic and plugin attributes. Each one is an Attr:

ctrl.translateX.value = 2          # read and write through .value
ctrl.t.value = (0, 1, 0)           # compounds take and return tuples
ctrl.rotateOrder.value = pk.RotateOrder.ZXY

ctrl.tx >> md.i1x                  # connect
ctrl.tx.connect(md.i1x, force=False)
ctrl.worldMatrix[0] >> dcmp.inputMatrix
remap.value[1].value_Position.value = 0.5

ctrl.lock_and_hide("scale", "visibility")
ctrl.unlock_and_show("scale")
twist = ctrl.add_attr("twist", min_value=-180, max_value=180)

>> returns nothing, so a chain like a >> b >> c raises an error instead of guessing what you meant. Write two lines.

Python members win. If a Maya attribute has the same name as a Python member, such as name or parent, the Python member is used. Reach the Maya attribute with node.attr("name"). The same goes for attribute names that are Python keywords: surface.attr("is").

Naming

Names follow [side]_part_part_suffix, built and read by naming. The default side tokens are L and R:

pk.compose("arm", "ik", side=pk.Side.LEFT, suffix="ctrl")   # 'L_arm_ik_ctrl'
pk.parse("R_leg_jnt")                                         # NameParts(side=Side.RIGHT, parts=('leg',), suffix='jnt')
pk.mirror("L_arm_ctrl")                                       # 'R_arm_ctrl'

with pk.use_convention(pk.Convention(left="lft", right="rgt")):
    pk.compose("arm", side=pk.Side.LEFT, suffix="ctrl")      # 'lft_arm_ctrl'

Helpers that create several nodes name them consistently from one base, for example L_arm_fk_ctrl under L_arm_fk_ctrl_ofst under L_arm_fk_ctrl_zr.

Undo and the selection

pkrig4 reads the scene through OpenMaya 2.0 (fast) and makes every change through maya.cmds, so every change is undoable. Wrap a build in undo_chunk to undo it in one step:

@pk.undo_chunk("build arm")
def build_arm(): ...

Nothing in pkrig4 depends on, or changes, the selection.

Results with several parts

Functions that create several nodes return a named tuple. Use the parts by name, or unpack them:

arm = controls.create_control("arm", "fk", side=pk.Side.LEFT)
arm.ctrl.rotate >> jnt.rotate
ctrl, offset, zero = arm

Fields are only ever added at the end, so unpacking stays valid across versions.
